# Pantalla de acceso (REQ-LOGIN) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reemplazar la funcionalidad de login de la portada según los tres requerimientos REQ-LOGIN: identidad + formulario (REQ-01), validación propia de campos vacíos (REQ-02) y caja de credenciales inválidas (REQ-03).

**Architecture:** Todo el trabajo es frontend (React SPA). La portada (`HomePage.jsx`) concentra el formulario; se le agrega validación propia en `handleSubmit`, un botón de ojo como componente aparte, y la Navbar pasa a ocultarse sin sesión (`Navbar.jsx`). Los estilos nuevos viven en `index.css` junto a los existentes. El backend, `AuthContext` y `client.js` no se tocan.

**Tech Stack:** React 19 + Vite, Vitest + Testing Library (jsdom), CSS propio, fuente Pixelify Sans via `@fontsource/pixelify-sans`.

**Spec:**
- `docs/requerimientos/REQ-LOGIN-01-portada-acceso.md`
- `docs/requerimientos/REQ-LOGIN-02-campos-vacios.md`
- `docs/requerimientos/REQ-LOGIN-03-credenciales-invalidas.md`

**Estado real del código (importante — los "estado actual" de los REQ están desactualizados):**

- REQ-03 ya está implementado (caja con título + ayuda, dentro del form, entre Contraseña y Acceder; "Error de red"; conserva datos). Sus tests existen en `HomePage.test.jsx` / `HomePage.integration.test.jsx` y pasan. **No se modifica**; esos tests son la red de regresión.
- REQ-01 parcialmente implementado: ya existe el logo (`assets/logo.png`), el tagline correcto, la línea pixel y no hay párrafo descriptivo. Faltan: título en mayúsculas, botón de ojo, ocultar Navbar sin sesión y la fuente Pixelify Sans.

## Global Constraints

- Tipografía única **Pixelify Sans** en todo `src/frontend`; prohibido `Courier New` (RNF-1.6).
- Textos exactos: título `¿CUÁNDO VENCE?`; tagline `Control de vencimientos de productos perecederos`; botón `Acceder`; campo: `Por favor, rellená este campo.`; general: `Campos incompletos` + `Por favor, completá los campos solicitados.`; error: `Credenciales inválidas` + `Revisá el usuario y la contraseña e intentá de nuevo.`; red: `Error de red` + `Revisá tu conexión e intentá de nuevo.`; aria-labels: `Mostrar contraseña` / `Ocultar contraseña`.
- Colores: advertencia ámbar — fondo `#2a2410`, borde/título `#d9b04a`, ayuda `#e8cf8f`; error rojo — fondo `#2a1a1a`, borde/título `#d45a5a`, ayuda `#e08a8a`.
- Sin validación nativa: sin atributo `required`, sin burbuja del navegador. Los mensajes aparecen solo al presionar **Acceder** (RF-2.5, RF-2.10).
- Campo "vacío" = `valor.trim() === ''` (decisión).
- No tocar `src/backend/`, `src/frontend/src/context/AuthContext.jsx`, `src/frontend/src/api/client.js` ni `HomePage.integration.test.jsx`.
- Única dependencia nueva permitida: `@fontsource/pixelify-sans`.
- Comandos siempre desde `src/frontend`: `npm test` (vitest run), `npm run lint` (oxlint).

## Review Focus

1. **Submit con la tecla Enter** en un input debe correr la misma validación que el botón y nunca disparar un request con campos vacíos → test "Enter" en Task 4.
2. **El botón de ojo no debe enviar el formulario** (`type="button"`) aunque los campos estén completos → test en Task 3.
3. **Borde ámbar vs. mensajes:** el borde se limpia al escribir (RNF-2.3) pero los mensajes persisten hasta el próximo intento (RF-2.8/2.10) → test en Task 4.
4. **La caja ámbar y la caja roja nunca coexisten:** un reintento vacío limpia el error previo y muestra solo la advertencia → test en Task 5.
5. **Valores con solo espacios** cuentan como vacíos (`trim()`) → test en Task 4.

### Task 4: Validación propia — un solo campo vacío

**Files:**
- Modify: `src/frontend/src/pages/HomePage.jsx` (`handleSubmit`, inputs, mensajes)

**Interfaces:**
- Produce (Task 5 consume): estados en `handleSubmit` — `missing: { username: boolean, password: boolean }` (faltantes del último intento; gobierna los mensajes) y `marked: { username: boolean, password: boolean }` (bordes ámbar; se limpia por campo al escribir). Constantes de texto: `FIELD_MSG = 'Por favor, rellená este campo.'`.
- Markup: `FieldMsg` = `<p className="field-msg" id="msg-username|msg-password" role="alert">…</p>` dentro del `form-group` correspondiente, debajo del input (o de `.password-wrap`); el input faltante lleva `className="input-error"` y `aria-describedby="msg-…"`.
- Regla de exclusividad: con **un** campo faltante se muestra el `FieldMsg` de ese campo; con **dos** faltantes no se muestra ningún `FieldMsg` (Task 5 muestra la caja general).
- Flujo de `handleSubmit` (decisión; las tareas 4 y 5 agregan sus piezas):

```
e.preventDefault()
limpiar error rojo (setError(null)) y showWarnBox(false)
faltan = [username si trim()==='', password si '']
si faltan.length > 0 → setMissing/setMarked por campo, foco al primer faltante, return   (sin request)
limpiar missing/marked → try loginUser(...) como hoy
```
